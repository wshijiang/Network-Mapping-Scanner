# 目标执行反馈

扫描端在正常任务完成后提供可选的执行耗时和目标 TCP 连接样本，帮助服务端按实际目标网络质量选择扫描器。无需手动配置可达网段。

采样只针对本任务发现的开放 TCP 端点，再次检查地址与端口是否属于任务范围。每次最多八个并行样本，每个最多等待 800 ms；纯 DNS、没有开放端口及不在目标范围内的观察不会触发额外连接。连接成功、拒绝、超时、明确路由错误和其他错误分别记录。

通过 `POST /api/scanner/task/performance` 使用现有运行令牌报告。报告最多等待两秒；旧服务端不支持该接口时仍继续原有结果上传。执行归属、租约、结果回执、检查点和协议版本不由反馈接口改变。服务端只在最终结果确认成功后使用这些指标。

连接拒绝说明收到目标网络响应；单次超时和零开放端口不等于不可达。任务执行遇到明确 OS 路由或源地址错误时，失败报告携带 `failure_class=route_unavailable`；其他失败使用 `scan_error`。服务端根据短期反馈重新排序节点，并由现有最多三次领取限制重试，不维护永久禁止关系。

推荐升级顺序为服务端、扫描端、前端。服务端默认智能分配；旧扫描端继续执行任务但不提供连接反馈。详见服务端 `docs/SMART_SCANNING.md`。
