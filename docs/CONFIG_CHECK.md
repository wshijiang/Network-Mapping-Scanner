# 启动配置检查

扫描器读取 `--config` 指定的原始 TOML，按字段路径识别未显式填写的参数，再沿用现有默认值与参数校验。文件部署和 Docker 部署使用相同流程，不改写配置，不需要将只读挂载改为可写。

启动终端输出摘要，JSON 日志记录 `ConfigCheckSummary` / `ConfigFieldDefaulted`。缺少 `scanner.c_server`、`scanner.c_port`、`scanner.rate` 或 `upload.endpoint` 时输出必要字段并拒绝启动。语法、类型、范围和功能依赖继续由原加载流程校验。

- 未启用引擎的配套参数作为可选项，不要求用户补齐。
- 引擎开关是本地部署限制，服务端远程配置不能开启本地禁用引擎。
- 工具和模板路径来自本地配置，按文件或 Docker 部署核对实际路径。
- 探测预算、DNS 等参数还可能受远程运行配置覆盖，检查展示的内置缺省值不是最终远程值。
- `scanner_id` 和 `runtime_token` 属于 SQLite 身份或历史迁移输入，不作为缺失提示，也不随检查报告发送。

启动快照通过心跳的可选 `local_config_check` 上报。支持该能力的服务端在管理员“扫描器 → 扫描配置 → 扫描器本地配置检查”展示；旧服务端可忽略该额外字段。扫描器停止或连接失败时无法更新报告，Web 应结合启动检查时间和最后回报时间判断。

修改文件后重启扫描器才能得到新快照；正常任务仍按原任务边界应用远程参数。该功能不改变只读挂载、身份数据库或待上传缓存，也不迁移字段名称与类型。

字段目录复用配置类型的默认值、序列化名称和 masscan 扁平字段；新增基础必需字段时应同步 `inspect_scanner` 并添加兼容测试。默认值与序列化结果只能取自不含凭据的内置原型，禁止输出实际用户配置。
